# 要件定義

## 目的・範囲

喫茶店の管理者・スタッフが、商品ごとの在庫と入出庫履歴を安全に管理するMVP。日本語UI、PC・タブレット対応を対象とする。複数店舗、発注連携、会計連携、一般公開のユーザー登録、棚卸しワークフローは初期対象外。

## 利用者と権限

| 操作 | 管理者 | スタッフ |
|---|---:|---:|
| ログイン・ログアウト | 可 | 可 |
| 商品一覧・在庫・履歴の参照 | 可 | 可 |
| 商品登録・編集・有効/無効切替 | 可 | 不可 |
| 入庫・使用・廃棄の記録 | 可 | 可 |
| 一般公開ユーザー登録 | なし | なし |

初期管理者は安全なCLIコマンドで作成する。パスワードはWerkzeugの安全なハッシュで保存し、平文を保存・表示しない。

## 機能要件

### 商品マスタ

- 商品コード（重複不可）、商品名、カテゴリ、単位、発注点を登録・編集・一覧表示する。
- 商品は物理削除せず、有効/無効状態を切り替える。無効商品も過去履歴から参照できる。
- 発注点は非負の固定小数点数量。商品単位と数量精度は業務上の最小単位に合わせ、初期精度を小数3桁とする。

### 在庫・入出庫

- 現在庫は商品の在庫移動台帳の有効な数量差分を合計して求める。台帳が在庫の唯一の根拠であり、独立して更新される在庫数列は持たない。
- 入庫は正の数量、使用・廃기는正の入力数量を受け取り、台帳にそれぞれ正・負の数量差分を追記する。
- 使用と廃棄は別の移動種別として履歴に残す。在庫不足の場合は記録せず、利用者に分かるエラーを返す。
- 全数量を `NUMERIC(12,3)` / Python `Decimal` で扱う。数量は正の入力でなければならず、在庫残高は常に0以上とする。
- 操作日時、操作者、対象商品、種別、数量差分、訂正理由を記録する。
- 同一商品の書込みはDBロックを介して直列化し、トランザクション内で残高検証と台帳追記を行う。

### 訂正と履歴

- 入出庫履歴は更新・削除しない。誤記訂正は理由と元履歴参照を持つ新しい訂正差分として追記する。
- 訂正後も全履歴を閲覧できる。訂正差分により在庫が負になる場合は拒否する。
- 履歴一覧で日時、商品、種別、数量、操作者、訂正理由を表示する。

### 検索・発注アラート

- 在庫一覧は商品名・カテゴリで検索できる。
- 現在庫が発注点以下の商品を明確に強調する。無効商品は既定では在庫一覧から除き、履歴では表示する。

### セキュリティ・画面

- ログイン必須とし、サーバー側で全ての権限を検査する。未認証はログインへ、権限不足は403へ誘導する。
- 状態変更はCSRFトークン付きPOSTとする。CSRFのないGETで状態を変更しない。
- 日本語のフォームラベル・エラー表示と、キーボード操作可能なレスポンシブ画面を提供する。
- `/health` は軽量な稼働確認を返し、秘密情報・接続情報を含めない。

## 受入条件

- 登録・編集・重複コード拒否、入庫、使用、廃棄、在庫不足拒否、履歴・訂正、発注アラートをテストする。
- ログイン・ログアウト、ロール別制御、同時出庫、マイグレーションをテストする。
- 単体テストはSQLite、PostgreSQL固有のロック・統合テストはCIの一時PostgreSQLで実行する。
- 本番Neonに対するテスト・初期化・デモデータ投入を行わない。

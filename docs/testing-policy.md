# テストポリシー

## 原則

- 新機能・修正はテストを先に追加し、未実装時に失敗することを確認してから実装する。
- テストは本番Neonに接続しない。専用の常設テストDBを作らない。
- SQLiteを単体・通常の統合テストに使用し、PostgreSQL固有の制約・行ロック・同時更新はGitHub Actionsの一時 PostgreSQL サービスで実行する。
- `DATABASE_URL` と `TEST_DATABASE_URL` を区別する。本番DBらしいURLを破壊的なテストコマンドが受け取った場合は、開始前に明示的に拒否する。
- `Decimal` で数量を検証し、浮動小数点の近似比較をしない。

## 必須シナリオ

- 商品登録、重複コード拒否、商品編集、無効化と権限
- 入庫、使用、廃棄、在庫不足拒否、履歴表示、追記訂正
- 発注点以下の強調表示
- ログイン・ログアウト、一般登録不可、管理者/スタッフ権限
- 同時出庫時に在庫を負にしないこと（PostgreSQL）
- マイグレーション適用・スキーマ作成
- `/health`、CSRFのある更新操作、未認証アクセス

## 実行コマンド

```bash
pytest
ruff check .
ruff format --check .
```

PostgreSQL統合テストは `TEST_DATABASE_URL` が明示されたCIジョブでのみ実行する。CIはPostgreSQLサービスをジョブ単位で起動し、終了時に破棄する。接続失敗やテスト失敗は明確に失敗として扱い、SQLiteへ黙って切り替えない。
